1 USO DE PUNTEROS

¿Qué es un puntero?

Toda variable vive en una dirección de memoria — como el número de una casilla. Un puntero es una variable especial que no guarda un valor "normal": guarda la dirección de otra variable. Es la tarjeta que dice en qué casilla está el dato.

int x = 10; // x vive en una dirección, ej. 0x7ffc10 int* p = &x; // p guarda la DIRECCIÓN de x cout << x; // imprime: 10 cout << &x; // imprime: 0x7ffc10 (la dirección de x) cout << p; // imprime: 0x7ffc10 (lo que guarda p) cout << *p; // imprime: 10 (el VALOR al que apunta p)
OperadorNombreQué haceEjemplo

*Declaración de punteroAl declarar, indica que la variable es un punteroint* p
*DereferenciaAl usarlo, accede al valor al que apunta*p

Cuidado: un puntero declarado sin inicializar (int* p;) apunta a "cualquier cosa". Siempre inicialízalo con una dirección válida o con nullptr.
2 MECANISMOS DE ASIGNACIÓN DE MEMORIA

Automática, estática y dinámica

En C++ toda variable vive en uno de tres lugares. La diferencia entre ellos es cuándo nace, cuándo muere y quién decide su tamaño.

PILA · AUTOMÁTICA
STACK0x7ffc10edad = 20
STACK0x7ffc14saldo = 5000.0

Nace al declarar. Muere sola al salir del bloque/función.

SEGMENTO ESTÁTICO
STATIC0x0602a0contador = 3

Nace una sola vez al iniciar el programa. Muere al terminar el programa completo.

MONTÓN · DINÁMICA
HEAP0x9a2201*saldo = 50000

Nace cuando se ejecuta new. Muere solo cuando se ejecuta delete (manual).

MecanismoDónde vive¿Cuándo nace?¿Cuándo muere?Sintaxis
Automática Pila (Stack) Al declarar la variable Al salir del bloque o función int edad = 20;
Estática Segmento estático (fuera de Stack y Heap) Una sola vez, al iniciar el programa Al terminar el programa static int contador = 0;
Dinámica Montón (Heap) Cuando se ejecuta new Cuando se ejecuta delete (si se olvida: fuga de memoria) int* p = new int(5);
Fuga de memoria (memory leak): si reservas con new y nunca haces delete, esa memoria queda "reservada" para siempre aunque ya no la uses.
3 ASIGNACIÓN DE MEMORIA A TIPOS PRIMITIVOS

int, double y demás tipos básicos

Los mismos 3 mecanismos aplican a variables primitivas (int, double, char, etc). Aquí es donde conviene aprenderlos primero, antes de dar el salto a objetos.

// AUTOMÁTICA — vive en el Stack, muere al salir de la función int edad = 20; // ESTÁTICA — conserva su valor entre llamadas a la función void contarLlamadas() { static int contador = 0; contador++; } // DINÁMICA — vive en el Heap, se reserva y libera manualmente int* saldo = new int(50000); cout << *saldo; delete saldo; // libera UN solo valor // Arreglo dinámico de primitivos int n = 5; double* montos = new double[n]; delete[] montos; // libera un ARREGLO -> siempre con []
SituaciónMecanismoPor qué
int edad = 20;AutomáticaVariable local común, tamaño fijo y conocido
static int contador = 0;EstáticaNecesita conservar su valor entre llamadas
new int(5)DinámicaNecesitamos que viva más allá del bloque actual, o su tamaño se decide en ejecución
Regla práctica: si no sabes de antemano cuántos datos vas a necesitar (por ejemplo, el usuario decide cuántas transacciones ingresar), esa es la señal de que necesitas memoria dinámica.
4 ASIGNACIÓN DE MEMORIA A INSTANCIAS DE CLASES

Objetos: automática vs. dinámica

Un objeto (una instancia de una clase, como Cliente o Cuenta) se crea exactamente igual que un primitivo: con variable normal (Stack) o con new (Heap).

OBJETO AUTOMÁTICO
STACK 0x7ffc40 Cliente c1("Ana", ...)

Se destruye SOLO al terminar la función — su destructor se llama automáticamente.

Cliente c1("102340567", "Ana"); c1.mostrarInfo(); // no hace falta liberar nada
OBJETO DINÁMICO
HEAP 0x9a3c10 Cliente(...)

Vive hasta que se libere con delete — si se olvida, hay fuga de memoria.

Cliente* c1 = new Cliente("102340567", "Ana"); c1->mostrarInfo(); // -> en vez de . delete c1; // libera y llama al destructor

Arreglos de objetos: estático vs. dinámico

// Arreglo ESTÁTICO: tamaño fijo, definido en tiempo de COMPILACIÓN Cuenta cuentas[3]; // siempre 3, ni una más // Arreglo DINÁMICO: tamaño definido en tiempo de EJECUCIÓN int capacidad = obtenerCantidadDeUsuario(); Cuenta* cuentas = new Cuenta[capacidad]; // ... usar cuentas[0], cuentas[1], etc. delete[] cuentas; // libera TODO el arreglo
DeclaraciónMecanismo¿Cómo se libera?
Cliente c1(...);AutomáticaSola, al salir del scope
Cliente* c1 = new Cliente(...);Dinámicadelete c1;
Cuenta cuentas[3];Estática (arreglo fijo)Sola, al salir del scope
Cuenta* cuentas = new Cuenta[n];Dinámicadelete[] cuentas;
Por qué importa para el paso de parámetros: pasar un objeto por valor a una función crea una copia completa. Pasarlo por referencia (&) o por puntero (*) trabaja sobre el objeto original — más eficiente y necesario si la función debe modificarlo de verdad.
